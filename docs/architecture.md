# Architecture

## 运行边界

```text
页面与组件
   │
   ├── 商品领域层 ── 演示数据 / 云数据库适配器
   │
   └── 试戴编排层
          ├── 追踪配置与锚点变换
          ├── VisionKit 会话适配器
          └── three.js 渲染适配器

微信云函数 ── 商家、商品、内容安全
腾讯云 COS/CDN ── GLB/glTF 与材质资产
```

页面只负责收集输入、展示状态和触发导航。纯计算逻辑放在 `miniprogram/tracking/`，可由 Node.js 测试直接加载。VisionKit 与 three.js 通过小接口隔离，避免真机 API 渗入变换测试。

## 首轮实现顺序

1. 用演示数据跑通商家页、商品详情和试戴入口。
2. 在真机上验证每个品类的 VisionKit 关键点可用性与稳定性。
3. 接入 three.js 微信适配层，先显示单个已知 GLB。
4. 加入尺寸校准、正反判定和会话清理。
5. 最后接入商家上传、云数据库与 COS/CDN。

当前仓库只完成第 1 步的工程骨架，以及第 2–4 步所需的纯逻辑接口。
